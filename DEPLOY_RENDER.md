## Deploy LooksGood on Render (public)

This repo includes a Render Blueprint at `render.yaml`.

### 1) Put this project in its own GitHub repo
Render reads `render.yaml` from the **root of the Git repo**.

- Make sure the repository root contains `render.yaml`, `backend/`, and `web-frontend/`.
- If your current Git repo root is not this folder, create a new repo from this folder (`Looksbook/`) and push it to GitHub.

### 2) Create the Render services from the Blueprint
1. Go to Render Dashboard → **New** → **Blueprint**
2. Connect your GitHub repo (the one that contains `render.yaml`)
3. Render will detect:
   - `looksgood-postgres` (PostgreSQL)
   - `looksgood-api` (FastAPI)
   - `looksgood-web` (static site)
4. Click **Apply**

Backend note:
- The API service uses `backend/Dockerfile` so `ffmpeg` is available in production (Render’s default Python runtime doesn’t include it).

### 3) Set required environment variables (Render → looksgood-api → Environment)
The Blueprint creates safe defaults, but you must set any feature keys you use:
- `OPENAI_API_KEY` (if using AI endpoints)
- `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` (if using Cloudinary uploads)
- `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` (if using payments)

Notes:
- `JWT_SECRET` is auto-generated by Render in `render.yaml` (change it only if you need to rotate it).
- `PUBLIC_BASE_URL` must be `https://...` (the backend enforces this in production).
- `CORS_ORIGINS` should include your real web origins (the backend rejects `*` in production).

### 4) Add custom domains (Render → Settings → Custom Domains)
Recommended setup:
- Backend: `api.looksgood.com` → attach to `looksgood-api`
- Website: `www.looksgood.com` (and optionally `looksgood.com`) → attach to `looksgood-web`

### 5) Update DNS at your domain registrar
In your registrar’s DNS settings for `looksgood.com`, create the records Render shows for each custom domain.

Typical patterns (Render will show the exact values to use):
- `www` is usually a **CNAME** to a Render hostname
- `api` is usually a **CNAME** to a Render hostname
- root `@` may be **A/ALIAS/ANAME** depending on your DNS provider

Wait for DNS to propagate, then verify:
- `https://api.looksgood.com/api/health`
- `https://www.looksgood.com/`

### 6) Point the mobile app at the public API
For production builds, set:
- `EXPO_PUBLIC_API_URL=https://api.looksgood.com/api`
- `EXPO_PUBLIC_WEB_FRONTEND_URL=https://www.looksgood.com/`

This repo’s `looksgood-app/eas.json` is updated to use `api.looksgood.com` for production.
